# Консольный калькулятор с DLL-плагинами (Windows, C++17)

## Возможности
- `+`, `-`, `*`, `/`, `^`, скобки и унарные знаки.
- Функции из DLL: `sin(x)` (угол в градусах), `ln(x)`, `sqrt(x)`.
- Загрузка DLL из `./plugins` во время запуска.
- Имя функции берётся из метаданных плагина, а не из имени DLL.
- Ошибки выражений и ошибки функций выводятся в консоль; один неудачный ввод не завершает программу.

## Сборка
Нужны Windows, CMake 3.16+ и компилятор C++17 (например, Visual Studio).

Из корневой папки проекта:
```sh
cmake -S . -B build
cmake --build build --config Release
```

После сборки исполняемый файл и папка `plugins` находятся в каталоге сборки.
Запускайте `calc.exe` из его каталога, чтобы относительный путь `./plugins` указывал на нужную папку.

## Примеры
```text
> 16 + 4 * (3 - 1)
24
> 2^4 + sin(90)
17
> ln(100)
4.60517018598809
> sqrt(81) + 1
10
> ln(-100)
Ошибка: ln определён только для положительных чисел.
> 4 / 0
Ошибка: Деление на ноль.
```

## Как написать новый плагин
DLL должна экспортировать `get_plugin_info`, возвращающий указатель на `PluginInfo`.
Поле `name` задаёт имя функции в выражениях, поле `function` — указатель на функцию `double(double)`.
Имя файла не используется для регистрации операции. Добавьте исходник DLL в CMake либо соберите DLL отдельно, положите её в `plugins`, и калькулятор обнаружит её при следующем запуске.

## Ограничение безопасности ABI
Плагины должны быть доверенными DLL, собранными с совместимым компилятором/runtime. Невалидный файл или отсутствующий экспорт обрабатывается, но никакой загрузчик не может безопасно восстановиться после произвольного падения или повреждения памяти внутри сторонней DLL. Не следует выбрасывать C++-исключения через границу ABI в production-коде; здесь обработка исключения из `ln` показана для учебной демонстрации в рамках одного toolchain.
